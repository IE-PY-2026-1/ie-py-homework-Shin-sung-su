## 🟨 [3차 과제: V3.0] 무한 루프와 메뉴 시스템 (반복문) - 향후 작성 예정
### **✨3차 과제 업데이트 내용:**
  * 내용
  * 이번 3차 과제에서는 기존에 하나의 긴 메인 함수 안에서 순서대로 진행되었던 여러 코드들을 각 기능과 역할에 알맞게 여러 함수들로 분리하여 프로그램을 재구성하였다.
  * 메인 메뉴 함수 안에서 사용자가 직접 원하는 메뉴를 선택하여 실행할 수 있도록 하였고, 그 기능을 실행할 때에만 적절한 함수를 호출하여 사용되도록 하여 프로그램을 활용성을 더욱 높였다.
  * 정보 입력 함수를 통해 입력받은 여러 종류의 값들을 한번에 return 하고 쉽게 관리하기 위해 리스트 형태로 보내고 받는 방식을 활용하여 많은 수의 데이터를 효과적으로 사용할 수 있게 하였다.
    
### **🤖 AI 파트너십 과정**
 1. **내용 1**
    * **프롬프트 요약:**  메인 메뉴 함수에서 4번 메뉴를 실행 할 때 발생할 수 있는 오류의 가능성 제시
    * **적용 내용:** len 함수를 통해 해당 함수가 호출 되기 전 데이터가 원하는 형태로 들어올 수 있도록 미리 검사하는 방향성 제시 (아래 문제2 부분에 자세히 서술)
    
### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** 메뉴에서 1번 정보 입력을 하지 않은 상태에서 다른 메뉴를 선택할 시 해당 메뉴의 함수들이 정상적으로 작동하지 않음
     * **원인:** 메인 메뉴도 함수를 이용함으로써 사용자가 정보 입력 메뉴를 직접 선택하여 입력하지 않는 이상 다른 함수들에 전해질 매개변수에 오류가 생김
     * **해결:** 사용자가 1번 외 다른 메뉴를 선택할 시 먼저 정보 입력 여부를 검사 한 후에 해당 메뉴의 함수가 실행되도록 함. 또한 각 메뉴마다 if 문을 통해 동일한 과정을 거쳐 데이터 존재 유무를 확인한다는 점을 이용하여 외부에 별도로 데이터 검사 함수를 만들어 코드를 좀 더 간략화 함
  2. **문제 2:** 4번 준비물 추천 메뉴에서 체감온도 값을 활용하여 핫팩을 추천해주는 항목이 있는데 3번 메뉴를 거치지 않을 경우 상황에 알맞지 않은 결과가 나올 수 있음
     * **원인:** 3번 메뉴에서 지수 계산 함수를 통해 계산한 체감온도의 값을 append를 통해 날씨 데이터 마지막 인덱스에 추가하는 과정이 있는데 만약 3번 메뉴를 실행하지 않고 4번 메뉴를 실행 할 경우 날씨 데이터 리스트의 마지막 값인 [-1]을 통해 준비물 추천 함수에 넘겨지는 데이터가 체감온도 값이 아닌 1번 메뉴에서 생성된 리스트의 기존 마지막 인덱스인 미세먼지의 값이 들어가게 됨
     * **해결:** 사용자가 4번 메뉴를 선택 할 경우 함수를 호출하기 전 날씨 데이터 리스트에 정상적으로 체감온도의 값이 추가되었는지 확인하기 위해 len 함수를 이용하여 리스트의 길이가 7보다 작은 경우에는 continue를 사용하여 사용자가 다른 메뉴를 선택하도록 함

     * **원인:** 메인 메뉴도 함수를 이용함으로써 사용자가 정보 입력 메뉴를 직접 선택하여 입력하지 않는 이상 다른 함수들에 전해질 매개변수에 오류가 생김
     * **해결:** 사용자가 1번 외 다른 메뉴를 선택할 시 먼저 정보 입력 여부를 검사 한 후에 해당 메뉴의 함수가 실행되도록 함. 또한 각 메뉴마다 if 문을 통해 동일한 과정을 거쳐 데이터 존재 유무를 확인한다는 점을 이용하여 외부에 별도로 데이터 검사 함수를 만들어 코드를 좀 더 간략화 함
  2. **문제 2:** 4번 준비물 추천 메뉴에서 체감온도 값을 활용하여 핫팩을 추천해주는 항목이 있는데 3번 메뉴를 거치지 않을 경우 상황에 알맞지 않은 결과가 나올 수 있음
     * **원인:** 3번 메뉴에서 지수 계산 함수를 통해 계산한 체감온도의 값을 append를 통해 날씨 데이터 마지막 인덱스에 추가하는 과정이 있는데 만약 3번 메뉴를 실행하지 않고 4번 메뉴를 실행 할 경우 날씨 데이터 리스트의 마지막 값인 [-1]을 통해 준비물 추천 함수에 넘겨지는 데이터가 체감온도 값이 아닌 1번 메뉴에서 생성된 리스트의 기존 마지막 인덱스인 미세먼지의 값이 들어가게 됨
     * **해결:** 사용자가 4번 메뉴를 선택 할 경우 함수를 호출하기 전 날씨 데이터 리스트에 정상적으로 체감온도의 값이 추가되었는지 확인하기 위해 len 함수를 이용하여 리스트의 길이가 7보다 작은 경우에는 continue를 사용하여 사용자가 다른 메뉴를 선택하도록 함

### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1:** ... 깃허브의 코드 스페이스 상에서 해당 프로그램을 실행할 때 파일 저장 기능을 사용하였을 때 'weather_report.txt'을 찾을 수 없음  
     * **원인:** ... with open()을 이용하여 파일을 열고 저장할 때 특정한 경로가 따로 지정되어있지 않다면, 파일은 현재 프로그램이 실행된 '현재 작업 폴더'에 만들어지지만 코드 스페이스와 같이 웹 환경에서는 그 프로그램이 컴퓨터 내부에서 실행되는 것이 아니라 컴퓨터 내부 파일에 저장되는 형태가 아님
     * **해결:** .. 가상 서버 환경에서 실행되어 만들어진 파일은 코드 스페이스에서 탐색기, 파일 트리 부분에 만들어진다는 것을 확인함
  2. **문제 2:** ... 정보 입력 함수에서 try-except 구문을 통해 ValueError로 잘못된 입력의 예외 처리가 진행되었을 때 다른 함수에 오류가 발생한 데이터가 넘어가는 문제가 발생함 
     * **원인:** ... 정보 입력 함수가 오류로 인해 종료 되는 시점에 저장된 잘못된 입력이나, 아직 입력 되지 못한 상태의 데이터들이 그대로 저장되어 다른 함수들의 기능에 영향을 주는 오류가 발생 함 
     * **해결:** .. except 구문 내부에 return []을 추가하여 기존에 넘어갔던 잘못된 리스트를 빈 리스트로 다시 덮어쓰기를 통해 초기화를 함. 이를 통해  4. 정보 입력 검사 함수에서 해당 리스트가 전달되면 빈 리스트가 False로 인식되어 다른 메뉴의 함수들이 오염된 데이터로 실행되지 않도록 막는 역할을 하고, 해당 리스트가 빈 리스트일 경우 1번 메뉴에서 '정보가 저장되었습니다' 라는 문구를 출력하지 않도록 하여 사용자가 정보 입력 단계에서 문제가 생겼다는 것을 바로 인지 할 수 있도록 함
